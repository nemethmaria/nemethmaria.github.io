Headings are a promise

A note on structure, from someone learning Markdown

Markdown is a very small language. A line that starts with # becomes a heading, a line that starts with - becomes a list item, and that is most of what you need. Because it is so small, it makes the structure of a text impossible to hide.

In a word processor you can make any line look like a heading just by making it bold and a bit bigger. In Markdown a heading is a heading, and the outline of the whole document is right there in the plain text. If the outline doesn't make sense when you read only the lines starting with #, the document won't make sense either.

That is a useful test for any guide. Each heading is a promise about what comes underneath it. A reader who skims the headings should be able to find their answer without reading every paragraph, and a reader who reads every paragraph should never be surprised by what a section contains.

Lists work the same way. If the items in a list aren't the same kind of thing, the list is really a paragraph in disguise. And if a paragraph is secretly a set of steps, it should probably be a numbered list.

None of this is new to editors. Markdown just makes it visible, which is why I like drafting in it before a text goes anywhere else.
